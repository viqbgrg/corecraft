## Problem · 到期和内存不足是两类删除原因

缓存容量有限，既要避免返回过期数据，也要在未到期键占满空间时决定下一次写入能否进入。TTL 规则和淘汰策略分别解决这两个问题。

## Why · 时间过去不会自动执行每一条删除

Redis 使用惰性访问检查与主动过期工作协调期限。一个已经到期的键可能暂时仍在内存，但读取应按逻辑不存在处理。只看内存驻留不能判断 TTL 是否仍有效。

## Mechanism · 期限、候选集合和访问顺序

TTL 查询用 -1 表示无期限、-2 表示键不存在。SET 未携带保留 TTL 的选项时会清除旧期限；EXPIRE 0 立即删除。教学 SET 的 TTL 输入为零表示不附加过期选项，与 EXPIRE 0 的语义不同。

noeviction 在容量不足时拒绝需要更多空间的写命令。allkeys-lru 可从所有键选择，volatile-lru 只从设置了期限的键选择。本课用精确最近访问序号展示 LRU，真实 Redis 常使用采样近似，也有 LFU、random、TTL 等其他策略。

模型将三个等大小条目作为容量，不等同于真实 maxmemory 的字节核算。主动周期最多看两个候选，写入准入前额外清理已到期键，便于把过期回收与未到期淘汰的原因区分开。

## Experiment · 对照三种结果

1. 初始 C 在时间一到期。推进一秒，表里仍有三个驻留键；GET C 返回 nil 并删除，过期计数增加。
2. SET D 填满三个条目，再 SET E，noeviction 拒绝，数据未被接纳。
3. GET A 刷新它的最近访问顺序，切 allkeys-lru，再 SET E，淘汰尚未到期的 B，达到目标。
4. 重置后用不带 TTL 的 SET 覆盖 B、C，TTL 都为 -1；volatile-lru 下没有候选，再写新键仍会失败。
5. 对某键执行 EXPIRE 0，TTL 查询返回 -2；观察主动周期如何清理其他到期键。

## Conclusion · 缓存命中需要时间与容量条件

本课不模拟 Redis 精确主动采样、LFU 衰减、复制端过期传播或内存碎片。精确 LRU 是可解释的教学基准，不是实际实现承诺。

TTL 控制数据能有效多久，淘汰策略控制容量紧张时谁被留下。应用必须接受未到期键也可能被淘汰，并为缓存 miss 或写入拒绝设计正确路径。
