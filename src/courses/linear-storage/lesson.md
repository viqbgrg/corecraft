## Problem · 有顺序，不等于放在一起

序列 `[10,20,30,40]` 描述了逻辑顺序，却没有说明内存怎样组织。数组把元素放在连续槽位，链表用 next 连接分散的节点。

## Why · 定位和修改是两笔开销

数组按索引定位是 O(1)，中间插入需要搬移后缀。链表修改链接可以是 O(1)，但只有头引用、没有目标前驱时，找到索引 k 通常需要 O(k) 次遍历。不能只计算修改、忽略定位。

索引从 0 开始，索引 3 是第四个元素。数组用 `base + 索引 × 元素大小` 定位，单链表则从 head 沿 next 走到目标。链表的节点编号是身份标记，不是逻辑索引；插入或删除之后，同一节点在逻辑序列中的位置可能改变。

O(1) 表示操作次数不随元素数增长，不等于“只做一次”或“现实耗时完全一样”。O(n) 表示最坏情况下需要随长度增长的工作；实际位置不同，遍历或搬移数量也不同。

## Mechanism · 不变量决定操作

数组保持索引与连续位置的对应：插入先从右往左搬移，防止覆盖尚未搬走的数据；删除从左往右补齐空位。链表保持从 head 沿 next 可达的顺序：新节点指向原后继，前驱指向新节点；删除时让前驱跳过目标。头部操作要更新 head。

可视化上方是逻辑顺序，下方是实际槽位或节点分配顺序。链表插入的新节点编号较大，但可能成为逻辑第一个元素，证明分配顺序不等于访问顺序。

### 数组为什么要从右边开始搬

在 `[10, 20, 30, 40]` 的索引 1 插入 25，需要先把 40 搬到索引 4，再把 30、20 分别右移，最后写入 25，得到 `[10, 25, 20, 30, 40]`。若先把 20 写到索引 2，就会覆盖尚未保存的 30。

删除则相反：先取出目标值，再把右侧元素从左到右依次补入，最后缩短长度。读取和删除只允许 `0 ≤ 索引 < 长度`；插入允许索引等于长度，表示追加到末尾。空结构只能在索引 0 插入。

### 链表怎样保持后续节点可达

若原来 `前驱 → 后继`，插入时让 `新节点.next = 后继`，再令 `前驱.next = 新节点`。如果插在头部，没有前驱，就改为更新 head。删除则让前驱跳过目标，直接连到目标的 next；删除头节点时让 head 指向原来的第二个节点。

只移动链接不会要求把后续所有节点搬到新的位置，但必须保存正确的后继引用，否则可能丢失后面的整段链。尾节点的 next 为 null，空链表的 head 也为 null。

### 同一输入下分别计数

保持四个初始元素，在不同索引插入一个值。本实验不统计分配成本；数组统计元素读写，链表统计遍历的节点与链接写入：

| 插入索引  | 数组：读 / 写 | 链表：访问 / 链接写 |
| --------- | ------------- | ------------------- |
| 0（头部） | 4 / 5         | 0 / 2               |
| 3         | 1 / 2         | 3 / 2               |
| 4（尾部） | 0 / 1         | 4 / 2               |

链表插入的两次链接写入是新节点的 next，以及前驱的 next 或 head。头部不必遍历，而只有 head 的尾部插入仍要找到尾节点。若实现另外维护尾指针，成本又会改变，不能遗漏这个前提。

## Experiment · 分别数两类操作

1. 重置，保留数组、操作索引 0、插入值 25，点击“在索引处插入”。预期逻辑序列为 `[25, 10, 20, 30, 40]`，读取 4 次、写入 5 次。指出为什么写入比读取多一次。
2. 点击“读取索引处元素”，返回 25；再删除索引 0，恢复原序列。读取一次只查看数据，不会移除它。
3. 点击“比较相同位置的插入”，两组都在当前四元素序列的索引 0 插入 25，对照表显示 4 / 5 与 0 / 2。对照不会修改当前结构。实际插入、删除和比较都已完成，实验目标达成。
4. 把操作索引改为 3，再比较，核对上表；也可改为 4 观察尾插。每次同时记录逻辑长度和索引，避免拿不同工作量作比较。
5. 选做：切换单链表会恢复初始四个元素。在头部插入 25，看到新节点 N4 成为 head，next 指向 N0。按照链接应读出 25、10、20、30、40，而不是按照节点编号排序。
6. 继续在索引 0 删除直到空，再插入一个值，验证 head 从 null 恢复。改变结构会重新开始，本模式的实验目标需要用本模式的操作完成。

## Conclusion · 大 O 需要说明前提

实验最多 12 个元素。计数分别表示数组元素读写、链表节点访问与链接写入，不是纳秒测量；分配、释放、容量扩张和 CPU 缓存代价未计入。真实链表还可能因指针追踪而降低局部性；真实动态数组也会付出偶发扩容代价。

自检：拿到“索引 3”和拿到“目标前驱的引用”，是同一个起点吗？前者在单链表上还需要遍历，后者可以直接修改链接。分析复杂度时，先写清已有的信息，再数定位和修改各自的开销。
