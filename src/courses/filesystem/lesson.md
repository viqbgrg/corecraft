## Problem · 删除命令与正在读取的文件

一个进程打开日志，另一个操作删除日志的文件名，原进程却还能继续读取。空间也可能没有立刻释放。这不是“删除失效”，而是名字与已打开对象具有不同的生命周期。

## Why · 名称不能承担所有身份关系

文件是字节内容与元数据的组织。目录项负责从名称找到对象；inode 保存长度、块映射等元数据；文件描述符 FD 是进程访问一个打开文件的入口。将三层关系分开，文件才能同时拥有多个名字，也能在名字改变后继续供已有使用者访问。

## Mechanism · 从名字到块，再到打开引用

本实验的根目录最初有 `note → inode 1`。inode 1 长度为 8，指向块 0 与 1，内容为 ABCD1234。每块 4 字节，文件尾部可以不足一块；空文件无需数据块。

`link note copy` 新增一个指向同一 inode 的目录项，nlink 从 1 变成 2，没有复制数据。通过任一名字改写内容，其他名字与已有 FD 都仍引用同一个对象。

`open` 查找名字，建立 FD 到 inode 的引用，偏移从 0 开始。`read` 按当前偏移取最多指定数量的字节并推进偏移；到达文件尾返回 0 字节，即 EOF。每次独立 open 的偏移互不影响；真实系统的 dup / fork 可以共享 open file description，本模型没有演示这部分。

`unlink` 只移除一个目录项。当 nlink=0，且没有打开引用时，才回收 inode 与数据块。`close` 释放一个打开引用，并再次检查回收条件。

## Experiment · 亲手移除最后一个引用

1. 打开默认 note，记录得到的 FD，再创建硬链接 copy。确认有两个名称，却仍只有一个 inode 和两个数据块。
2. 删除 note。将文件名改为 copy，删除第二个名字。此时目录为空，但 inode 与块还在。
3. 用原 FD 读取，确认得到 ABCD。再读一次得到 1234，再读则为 EOF；也可以 seek 回到开头。
4. 关闭最后的 FD，观察 inode 与块被回收，实验目标完成。
5. 重置后打开同一文件两次，比较偏移；或创建多个文件填满磁盘，观察容量不足时旧内容保持完整。

## Conclusion · 文件系统还有持久化与权限层面

这是单目录、单进程模型，最多 8 个 inode、16 个目录项、8 个打开 FD 和 12 个数据块；内容限定为可打印 ASCII，最多 24 字节。inode 与 FD 编号单调增加，省略真实编号复用。

“替换全部内容”是本课的原子教学操作，不是对所有 POSIX write / truncate 组合的原子性承诺。模型未实现权限、目录硬链接、符号链接、稀疏文件、日志、崩溃恢复或跨文件系统链接。下一课再区分修改内存中的文件页与真正写到磁盘。
