## Problem · 有限比特不能装下所有实数

0.5 可以精确写成二进制 0.1；0.1 的二进制展开却无限循环。另一个现象是 32 位浮点中 16777216+1 仍然等于 16777216。它们都来自离散表示，但前者是输入舍入，后者暴露量级增长后的间距。

## Why · 范围与精度是不同资源

定点数固定小数点位置；浮点数把有效数字和缩放指数分开，在有限位宽内覆盖很小到很大的量级。指数扩大范围，却不增加每个量级上的有效位数。误差必须联系量级、运算顺序和具体业务要求判断，不能机械地用一个固定 epsilon 解决所有比较。

## Mechanism · binary32 的编码与舍入

IEEE 754 binary32 有 1 位符号 s、8 位指数域 E、23 位小数域 F。

| 指数域        | 数值或分类                              |
| ------------- | --------------------------------------- |
| 1..254        | 正规数：(-1)^s × (1+F/2^23) × 2^(E−127) |
| 0 且 F 非零   | 次正规数：(-1)^s × (F/2^23) × 2^(-126)  |
| 0 且 F=0      | 正零或负零                              |
| 255 且 F=0    | 正无穷或负无穷                          |
| 255 且 F 非零 | NaN                                     |

正规数隐含前导 1，具有 24 位有效二进制精度。越接近更大的 2 的幂，相邻数间距越大；次正规数允许在最小正规数以下逐渐损失相对精度，而不是立即全部变成零。

本实验采用 round-to-nearest, ties-to-even：取最近可表示值，恰好位于中点时选有效数字最低位为偶数的值。加法先分别把两个输入舍入为 binary32，再对它们的精确值求和并舍入结果。参考列保留原十进制字符串的精确数学值，因此总误差包括输入误差与运算误差。

## Experiment · 把近似值与精确值放在一起

1. 默认计算 0.1+0.2，观察编码 `0x3E99999A`、精确目标 3/10 与结果误差 1/83886080。
2. 比较三组例子，确认 0.5 没有表示误差。
3. 输入 16777216 和 1，再把 B 改为 2。第一组发生中点舍入，第二组可以精确表示。
4. 选择仅转换 A，输入 `1e-45` 观察次正规数，输入 `-0`、`Infinity` 或 `NaN` 观察特殊编码。NaN 不是一个可以正常排序的实数。

## Conclusion · 明确所讨论的精度

实验使用精确 BigInt 有理数直接舍入到 binary32，避免先转 binary64 再转 binary32 的双重舍入。十进制输入最多 24 位数字，显式指数为 −60..60；只演示转换与加法，不实现全部 IEEE 异常标志、舍入模式或 NaN payload 传播。

JavaScript Number 通常是 binary64，Java float 是 binary32，Java double 是 binary64。这一课的结果不能直接等同于浏览器控制台普通数值表达式的结果。金额等需要十进制语义的场景还要考虑整数最小单位或十进制数值类型。
