## Problem · 比特没有自带正负号

8 位的 `11111111` 按无符号整数解释是 255，按补码解释是 −1。比特完全相同，差别来自解释规则。若把最高位简单当成加法器的“溢出标志”，就会混淆结果与运算标志。

## Why · 固定空间里的负数与算术

n 位只能表示 2^n 个不同状态。补码将这些状态分给 −2^(n−1)..2^(n−1)−1：正负范围不对称，零只有一种表示。最高位权重为负，其余位保持原来的正权。例如 8 位 `11111111` = −128+64+32+16+8+4+2+1 = −1。

补码让加法器保留低 n 位就能执行模 2^n 算术。负数 −x 的编码可由 x 按位取反再加一得到，但最小负数的相反数超出同一有符号范围。

## Mechanism · 逐位加法与两个独立标志

每一位计算 `A位 + B位 + 输入进位`：低位作为结果，高位送到下一位。减法使用 `A + NOT B + 1`，最低位初始进位为 1。

Carry 是最后向位宽之外送出的进位，回答无符号加法是否越界。减法的 Carry=1 表示无无符号借位，本实验也直接显示这个含义。

Overflow 回答数学结果是否超出补码范围，等于进入符号位和离开符号位的进位异或。加法中，同号操作数得到异号结果会溢出；异号相加不会有符号溢出。

| 8 位运算 | 补码结果 | Carry       | Overflow |
| -------- | -------- | ----------- | -------- |
| 127 + 1  | −128     | 0           | 1        |
| −1 + 1   | 0        | 1           | 0        |
| −128 − 1 | 127      | 1（无借位） | 1        |

## Experiment · 用反例拆开两个概念

1. 默认 127+1，单步计算直到符号位，再完成全部位计算。
2. 对比三组反例，找出 Carry 与 Overflow 不相同的行。
3. 输入 A=−1、B=1。先预测两个标志，再计算，确认结果为 0。
4. 切换 4 位，边界变为 −8..7。做 7+1 与 −8−1；改变位宽会重置为该位宽的边界例子。

## Conclusion · 区分硬件结果与语言规则

实验真实计算 4 / 8 位补码位轨迹，不包含乘除法、饱和算术或其他数值编码。越界后保留低位是本模型的行为；具体语言对有符号溢出可能规定回绕、抛错或未定义行为，不能仅凭这张加法器表推断。Java 的 int 使用 32 位补码算术，但宽度与这里不同。
