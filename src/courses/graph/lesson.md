## Problem · 更少的路口，不一定更快

一条路线经过 3 条边，总权重 9；另一条经过 4 条边，总权重 8。若权重表示耗时，更少的边并不保证更快到达。

## Why · 先定义图和目标

顶点表示对象，边表示联系。无向边双向可走，有向边只沿箭头方向。权重来自输入，图形中的线长没有算法意义。图可以含环，也可以有不可达顶点；不能假定每次都像树一样只有一条路径。

实验中 `A-B:4` 表示 A 与 B 之间有一条权重为 4 的边。无向模式下可以双向走；有向模式下只表示 A → B。权重可以是耗时、距离或成本，但一次比较中必须统一含义。

先区分三个问题：能不能到达、最少经过几条边、最小累计权重是多少。BFS、DFS 与 Dijkstra 使用不同的扩展顺序，正是因为要维持的保证不同。

## Mechanism · 不同的数据结构决定扩展顺序

**BFS** 从队首取顶点，首次发现邻居时入队并记录前驱，按层扩展，保证最少边数。**DFS** 从栈顶深入，回退后继续探索，能找出一条可达路径，但不保证最短。本实现的 DFS 候选携带父节点，在弹出时才确定访问，已访问的重复候选跳过。

**Dijkstra** 选暂定距离最小的未访问顶点，再尝试 `dist[v] > dist[u]+weight` 的松弛。边权非负时，新绕路不会把已经确定的最小距离降低；允许负权会破坏这个保证。前驱指针可以从目标逆向还原路径。

邻接表只列出现有边，邻接矩阵给每对顶点一个位置，各自适合不同密度。此实验保存边列表，查邻居时扫描它，并直接排序小型候选集；展示的是选择规则，不声称采用高性能优先队列。

### 等待扩展与已经确定

| 算法     | 下一顶点怎样选 | 距离或前驱的含义         |
| -------- | -------------- | ------------------------ |
| BFS      | 先进先出的队首 | 按层发现，距离记边数     |
| DFS      | 后进先出的栈顶 | 沿探索分支形成一棵前驱树 |
| Dijkstra | 暂定距离最小者 | 选中时确定最小累计权重   |

待扩展集合常称 frontier。BFS 首次发现邻居时就记录它，避免重复入队；本课 DFS 允许候选携带不同父节点入栈，弹出时才确认访问，之后跳过重复候选。二者都需要区分已访问与未访问，才能处理环。

对 Dijkstra，**发现一个距离不等于这个距离已经最终确定**。例如从 A 直接到 B 暂记 4，之后经过 D 的路线可能把它改小。只有从候选中选出当前最小距离的顶点时，非负边权才保证它不会再被更晚绕来的路线改得更小。

### 默认图的松弛过程

从 A 出发，先令 dist[A] = 0，其他距离为 ∞。每次只比较已有路线与经过当前顶点的新路线：

| 确定的顶点 | 主要更新             | 原因                                |
| ---------- | -------------------- | ----------------------------------- |
| A，距离 0  | B = 4，D = 2         | 使用 A 的直接出边                   |
| D，距离 2  | B 从 4 改为 3，E = 6 | 2 + 1 < 4，更新 B 的前驱为 D        |
| B，距离 3  | C = 6                | 3 + 3 = 6                           |
| C，距离 6  | F = 8                | 6 + 2 = 8；同距离时先选字母较小的 C |
| E，距离 6  | F 仍为 8             | 经 E 的 6 + 5 = 11 更大             |
| F，距离 8  | 目标距离确定         | 可按前驱还原路径                    |

由 F 沿前驱回到 C、B、D、A，再倒转，得到 `A → D → B → C → F`，权重为 `2 + 1 + 3 + 2 = 8`。BFS 则首先找到三条边的 `A → B → C → F`，总权重为 9。BFS 的距离表按边数记，路径权重另行相加，不能混为一个单位。

若目标始终不可达，距离保持 ∞，也没有从起点连过去的前驱链。不要把它解释为距离 0；距离 0 可以表示起点自身，也可以来自合法的零权边。

## Experiment · 改变同一张图

1. 重置，默认 BFS、无向图、A 到 F。单步观察 A、B、D 的扩展顺序，以及队首取出、队尾加入的变化。运行到底，再点击“对比三种图算法”，BFS 路径的边数为 3、权重为 9。当前遍历结束并生成对照后，实验目标达成。
2. 切换 Dijkstra，对照上表逐次推进。特别记录 B 的距离从 4 改为 3，以及前驱从 A 改为 D 的时刻。运行并比较，最终路径权重应为 8。
3. 切换 DFS，观察栈顶位于右端，追踪一个候选携带的父节点。运行到底并重新点击“对比三种图算法”，检查每个顶点只被正式访问一次，即使候选里曾有重复项。
4. 选做：使用 Dijkstra，把边改为 `A-B:0 B-C:2`，起点 A、目标 F。运行后 F 不可达；再把目标改为 C，结果应为 A → B → C、权重 2。零权边可以使用，∞ 表示无法到达。
5. 在这组两条边上改为有向图、起点 B、目标 A，重新运行，应不可达。再改回无向图，同样起终点就可到达，权重为 0。
6. 输入 `A-B:-1`，确认负权被拒绝；修正为合法输入后再运行。此限制来自当前算法的前提，不表示现实问题永远没有负权。

记录 **同一组边、方向、起终点、候选顺序、前驱、路径边数与权重**。改图、算法或起终点会重新开始，旧对照不再代表新问题。

## Conclusion · 最短必须说明度量

固定 A–F 六个顶点，最多 20 条唯一边，权重 0–20；不支持平行边和自环。邻接顶点按字母顺序，Dijkstra 同距离也按字母选择，所以轨迹可复现。对照使用相同边、方向、起终点与独立初始状态。

标准邻接表 BFS / DFS 为 O(V+E)；使用堆的 Dijkstra 常见界为 O((V+E)log V)，本教学实现没有使用该优化。负权最短路、拓扑排序与网络流不是本课模型的一部分。

自检：BFS 没选权重为 8 的路径，是计算错误吗？它正确优化了边数，而那条路线有四条边。先确定目标函数与边权前提，再选择算法，才能判断结果是否满足问题。
