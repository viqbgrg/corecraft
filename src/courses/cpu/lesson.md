## Problem · 代码不是魔法

入门课的小机器按照“读入 → 处理 → 输出”执行。现在打开它的内部：写下 `MOV R1, 10`，数字还不会凭空出现在寄存器里。CPU 需要知道从哪里读取指令、要求什么操作、用哪些输入，以及把结果写到哪里。

本课不要求会写汇编。把 `MOV` 读作“放入一个值”、`ADD` 读作“相加”、`STORE` 读作“存到内存”、`LOAD` 读作“从内存读取”，就能跟上实验。

## Why · 把执行拆成可控制的步骤

用 PC 记住下一条指令的位置，用指令寄存器 IR 保存当前指令，用寄存器保存操作数，用 ALU 完成计算。每个部件只承担一部分工作，控制逻辑让它们按顺序配合。

| 部件                | 本课中保存或处理什么 | 可以观察什么                 |
| ------------------- | -------------------- | ---------------------------- |
| PC（程序计数器）    | 下一条待取指令的位置 | 取指后从 0 变成 1            |
| IR（指令寄存器）    | 已取出的当前指令     | PC 已前进，IR 仍保留当前 MOV |
| R1、R2、R3          | 操作数和已写回结果   | 执行前后数值是否改变         |
| ALU（算术逻辑单元） | 加法等运算           | 两个输入以及算出的和         |
| 数据内存            | 通过地址保存的数据   | `Memory[0x10]` 的内容        |

地址与内容需要分开：`0x10` 是位置编号，对应十进制 16；这个位置可以存放 30，并不要求内容也等于 16。寄存器名同样用于定位，R1 不是数字 1。

## Mechanism · Fetch → Decode → Execute → Write Back

**Fetch** 读取指令并推进 PC；**Decode** 识别操作码与操作数；**Execute** 计算或读取数据；**Write Back** 把暂存的结果写入寄存器或内存。HALT 让教学 CPU 停止。

PC 前进并不代表当前指令已经写回。观察两者的时机差异，是理解执行状态的关键。

### 跟踪一条 MOV

默认程序开始时 R1 = 0。下面各行表示**完成该步骤以后**的状态；界面按钮显示的是接下来要执行的步骤。

| 刚完成的步骤 | PC  | R1  | 已经发生的事            |
| ------------ | --- | --- | ----------------------- |
| 尚未开始     | 0   | 0   | 还没有取指令            |
| Fetch        | 1   | 0   | IR 保存 `MOV R1, 10`    |
| Decode       | 1   | 0   | 识别目标 R1 和立即数 10 |
| Execute      | 1   | 0   | 10 已暂存，等待写回     |
| Write Back   | 1   | 10  | R1 现在才得到新值       |

“立即数”就是直接写在指令里的数，例如 10；`ADD R1, R2` 的第二个输入则来自 R2 的内容。两者取得操作数的方式不同。

### 把多条指令接起来

默认“加法 → 存储 → 读取”程序依次完成：

```text
MOV R1, 10       R1 ← 10
MOV R2, 20       R2 ← 20
ADD R1, R2      R1 ← R1 + R2
STORE [0x10], R1  内存[0x10] ← R1
LOAD R3, [0x10]   R3 ← 内存[0x10]
HALT             停止执行
```

ADD 的 Execute 得到 30 时，R1 还是 10；Write Back 后才变成 30。STORE 把 30 复制到内存，R1 仍保留 30；LOAD 又把该内存位置的内容复制到 R3。**复制数据不会自动清空来源。**

## Experiment · 寻找状态真正改变的瞬间

1. 重置后保留“MOV R1 的值”为 10、“MOV R2 的值”为 20，示例选择“加法 → 存储 → 读取”。连续点击三次单步，对照上表：PC 已经是 1，ALU 显示直通 10，R1 仍是 0。
2. 点击“单步 · Write Back”，确认 R1 = 10。用“执行完当前指令”完成第二条 MOV，R2 应为 20。
3. 对 ADD 单步执行 Fetch、Decode、Execute，停在写回之前。记录 **PC = 3、ALU 的和 = 30、R1 = 10、R2 = 20**；再写回，确认只有目标 R1 变成 30。
4. 继续跟踪 STORE 与 LOAD。预期先看到内存 0x10 变成 30，再看到 R3 变成 30；R1、R2 不会因传送而清空。执行 HALT 到停止，本课实验目标达成。
5. 选做：重置后把两个输入改为 7 和 9，再运行一次，预测 R1、内存 0x10、R3 都为 16。输入在开始执行后会锁定，换输入需要先重置。

如果数值与预测不同，先看 IR 是哪条指令、按钮表示哪一个下一阶段，再检查源操作数。不要只凭 PC 判断当前运算已经完成。

## Conclusion · 程序是状态转换的规则

本实验使用自定义教学指令集、16 位无符号寄存器与按指令编号的 PC。没有流水线、乱序、真实指令编码和异常；四个“微步骤”也不是现实 CPU 每条指令固定消耗的四个时钟周期。

自检：PC = 3 能否单独证明 ADD 已经写回？不能，它在取出第三条指令后就是 3，还需要结合阶段和寄存器判断。这里把结果计算与写回分开，是为了看清状态变化；现代处理器还会有更复杂的执行与提交机制。

接下来的流水线课程研究怎样让多条指令的阶段重叠，Cache 课程研究取数据时为什么会等待。它们都以本课的部件和数据流为起点。
