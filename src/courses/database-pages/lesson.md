## Problem · 行很小，IO 却按页发生

SQL 查询可能只需要一条记录，但存储引擎通常把它所在的整页读入内存。接着读同页的其他记录，可能完全不需要再读磁盘。理解数据库性能，需要同时看到逻辑表和物理页。

## Why · 用模式管理数据，用页管理存储

数据库组织表、模式与约束。表是逻辑上的记录集合，每行包含类型明确的字段；主键约束要求标识唯一。关系表本身不保证某个物理顺序，查询若要求顺序，需要相应的 ORDER BY。

存储引擎把记录放到数据页。页头、槽目录、记录内容都会占空间，页能容纳多少行取决于这些开销和记录长度。变长记录、删除空间及页分裂会让真实布局更复杂。

## Mechanism · 缓冲帧、dirty 与 pin

本实验数据库 academy 有一张 scores 表，记录为三个 4 字节整数 id、score、group。数据页为 64 B，页头占 16 B，每条记录 12 B 加一个 4 B 槽项，因此每页最多三条记录。六个页最多容纳 18 条记录，初始有九条。

Buffer Pool 缓存数据页。访问已驻留页计为命中；未命中时读入整页。如果帧满，选择 pin=0 的 LRU 页回收；脏页先写回，干净页可直接替换。

pin 是使用引用：引用未释放时，页不能被回收成另一个页面。dirty 表示内存页与磁盘页不同。事务锁用于协调事务之间的读取和修改，不能把 pin、dirty 和事务锁看作一个标志。

数据库 Buffer Pool 与操作系统 Page Cache 是不同的管理层。具体引擎和 IO 配置可能使用直接 IO 避免双重缓存，也可能经过系统缓存；不能仅凭存在 Buffer Pool 就断言下层缓存一定没有作用。

## Experiment · 让每个标志都产生可见行为

1. 读取并 pin 页 0，再次读取观察 Buffer Pool 命中增加、磁盘读取不增加。
2. 尝试回收当前缓冲页，观察 pin 阻止回收；释放一次 pin 后重试。
3. 插入默认 id=10 的记录，系统选择有空槽的页，内存逻辑表出现记录，磁盘页仍没有它。
4. 写回全部脏页，确认磁盘包含该记录。观察过命中、pin 拒绝与修改写回后，实验目标完成。
5. 也可以 pin 两个不同页，在容量为 2 时读取第三页；全部帧被占用时无法回收，必须先释放引用。

## Conclusion · 本课先分清存储单位

记录长度、页大小和表容量都是教学值。操作不是完整 SQL 执行器，按主键定位使用模型元数据，未模拟索引查找成本；下一课的查询路径会使用实际 B+Tree。整页同步写回也不表示事务已提交。

这里没有事务、WAL、并发、闩锁、校验和、变长记录或页压缩。特别是“脏页写回”必须与日志顺序结合才能支持崩溃恢复，下一课会补上这一条件。
