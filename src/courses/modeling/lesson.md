## Problem · “它会算”还不是一个解释

输入 3，机器输出 3、2、1，然后停止。是按钮预先藏好了答案，还是一组规则真的产生了结果？一个有用的解释应当能预测输入变成 2 会怎样，也能指出为什么输入 0 会让这段程序偏离原来的目的。

## Why · 从问题到可检验的机制

计算机接收、存储和处理数据，按照程序控制执行。学习时先问“它解决什么问题”，再选择解释这个问题需要的状态与规则。本课要解释倒数，不需要先模拟晶体管、电压或操作系统。

抽象不是随意忽略细节：必须说明保留了什么、预测哪些现象、在哪些边界失效。提出一个预测，执行一步，比较观察与猜想；不一致时先检查前提，再修改解释。正确预测一次只是证据，不是对所有输入的证明。

## Mechanism · 数据、状态、指令与程序

数据是输入整数与输出的值。运行状态包含累加器 ACC、程序计数器 PC、输出流和是否停机。指令规定状态怎样变；程序是一组有顺序、允许跳转的指令。这里行号从 0 开始。

| 指令                  | 状态变化                          |
| --------------------- | --------------------------------- |
| IN                    | 将固定输入读入 ACC，PC 加一       |
| SET n / ADD n / SUB n | 设置或修改 ACC，PC 加一           |
| OUT                   | 将 ACC 追加到输出，PC 加一        |
| JNZ line              | ACC 非零时跳到 line，否则 PC 加一 |
| HALT                  | 停止执行，PC 留在停机指令         |

默认程序为 `IN; OUT; SUB 1; JNZ 1; HALT`。先读取 3，再输出、减一、检查是否非零。ACC 到 0 时不再跳转，执行 HALT，共执行 11 条指令。程序本身没有展开三份 OUT，循环由状态与跳转实现。

## Experiment · 预测先于观察

1. 将“预测下一步 ACC”设为 3，验证预测并单步。检查 IN 是否符合解释。
2. 逐步执行 OUT、SUB、JNZ，分别预测 ACC 与 PC；然后运行至 HALT，确认输出为 3、2、1。
3. 将输入改为 2，先猜输出与指令数，再运行。调整输入会重新开始实验，先完成一次正确预测。
4. 输入改为 0：先输出 0，再减到 −1，之后无法依靠减一到达 0。每次运行最多 200 步，预算暂停不等于 HALT，也不是一般性的“不停机证明”。
5. 改成 `IN; ADD 2; OUT; HALT`，检验你是否能用同一套规则解释另一个问题。

## Conclusion · 模型必须有边界

本机支持最多 16 条指令，操作数与输入为 −99..99；ACC 越出模型安全范围会报告执行错误。程序越界也会报错，不能把缺失 HALT 当成正常停机。日志与输出窗口有显示上限，输出总数独立计数。

这是确定性的教学解释器，不是实际 CPU 指令集，也不通过 JavaScript eval 执行输入。程序与数据分开表示，省略二进制编码、内存地址、硬件并行和外部 IO。后续 Binary 与 CPU 课程会逐步增加这些细节。
