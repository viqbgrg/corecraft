## Problem · 同样多的工作，等待可以不同

三个任务分别在 0、1、2 时刻到达，需要 8、4、2 个 CPU 时间单位。总工作量都是 14，为什么切换策略后，用户感受到的等待会改变？

## Why · 先说明优化什么

批处理希望减少平均周转，交互请求更关心响应，长期服务还需要公平。**完成时间−到达时间**是周转；**首次运行−到达时间**是响应。本课只有 CPU 工作，所以**等待=周转−执行量**。真实任务的 IO 等待需要单独核算。

## Mechanism · 四种选择规则

**FCFS** 按到达顺序执行，一个长任务可能形成队头阻塞。**SJF** 在 CPU 空闲时选择已到达任务中最短的，不打断当前任务。**SRTF** 每个边界选择剩余工作最少者，后来到达的短任务可以抢占。SJF / SRTF 需要知道或估计执行时间，真实内核不能预知所有未来工作。

**RR** 让任务最多连续执行一个时间片，再排到队尾。短时间片改善响应，却可能增加上下文切换开销。本模型的切换计数记录相邻非空闲格中执行者的变化，首次分配与空闲转换不计；切换耗时暂为零。

任务的保存状态可看作 PCB / 线程控制块的一部分：身份、到达、剩余执行量与首次运行时刻。本课没有寄存器与私有栈，它们在进程与线程课中观察。用户线程由运行库管理，内核线程由操作系统调度；一个用户线程阻塞是否拖住同进程其他执行流，取决于两者的映射方式。

## Experiment · 保持工作负载不变

1. 使用默认 `0:8, 1:4, 2:2`，逐步执行 FCFS，观察 P2 和 P3 已到达时 CPU 仍执行 P1。
2. 运行全部任务，再比较四种策略。FCFS 平均等待为 17/3，SRTF 为 8/3；对照表来自真实独立运行。
3. 切换 SRTF，观察 t=1 抢占 P1，t=2 再抢占 P2。输入 `0:8, 0:4, 0:2`，看看 SJF 与 SRTF 是否仍有区别。
4. 切换 RR，把时间片从 1 改为 4，比较响应与任务切换。改输入会清除之前的运行与对照结果。
5. 输入 `3:2, 6:1`，观察没有就绪任务时的 IDLE；调度器不能执行尚未到达的任务。

## Conclusion · 策略服务于目标

本模型单核、离散时间、最多 8 个任务，没有 IO、优先级、多核、切换耗时或饥饿消除。到达事件先于同一边界的 RR 重新入队；SJF / SRTF 同分按到达与输入顺序，SRTF 不为相同剩余时间抢占。平均指标只在全部完成后显示，避免把只完成的短任务当作完整结果。

观察到 SRTF 的平均等待较低，不能推出它在所有系统里都最好：现实还要考虑估计误差、公平性、长任务饥饿和切换成本。
