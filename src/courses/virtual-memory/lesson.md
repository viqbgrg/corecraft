## Problem · 地址需要稳定，物理位置却会改变

多个进程可能都使用地址 0x012C，但它们不应该因此共享数据。物理内存有限，也未必有一整块连续空间容纳程序。

## Why · 加一层映射，解耦两个视图

程序看到虚拟地址；硬件结合当前进程的页表找到物理地址。不同页表可以把同一个虚拟地址指向不同物理帧。这个实验固定观察**一个进程**的页表，进程隔离的意义由前一课建立。

## Mechanism · 页号变化，偏移不变

本模型每页 256 B：VPN = 虚拟地址 ÷ 256 取整，Offset = 虚拟地址 % 256。页表给出 PFN 后，物理地址 = PFN × 256 + Offset。

TLB 首先缓存转换结果。TLB Miss 时继续查页表，只有 Present = 0 才在本模型中触发缺页。操作系统分配帧、载入数据、更新映射，之后重试原访问。

## Experiment · 分清两种“找不到”

1. 访问 0x012C（300），查页表，确认 VPN = 1、Offset = 44，PFN = 0。
2. 再次访问相同地址，观察 TLB Hit。
3. 访问 0x022A，查页表触发缺页，再处理缺页并重试。
4. 继续访问新页。4 个物理帧用满后会进行 FIFO 置换，旧 TLB 映射也必须失效。

## Conclusion · 缓存缺失不等于数据缺失

本实验有 8 个虚拟页、4 个物理帧和 2 项 LRU TLB，省略多级页表、权限检查、脏页和真实磁盘延迟。页面置换采用 FIFO 教学策略，不能据此推断真实操作系统的全部行为。
