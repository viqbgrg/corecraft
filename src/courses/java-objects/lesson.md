## Problem · 同一参数，两种修改

Java 方法 `change(Box p)` 接收 a。方法里先执行 `p.value = 20`，再执行 `p = new Box(30)`。返回 main 后，a 的对象字段改变了，但 a 没有指向新对象。

如果只说“对象在堆上”或“Java 传引用”，都不能准确说明是哪一个存储位置发生了改变。

## Why · 对象身份与变量需要分开

Object 有身份、Class 和实例字段；Reference 是指向对象的值，也可能是 null。变量保存引用值，`b = a` 复制这个值，不创建第二个 Box。两个对象即使字段完全相同，也可以有不同身份。

方法调用创建栈帧，局部变量、参数和返回相关状态属于这次调用。多个线程有各自的栈，但能够引用共享堆对象；线程间可见性还有 JMM 的规则，本课先只讨论顺序执行。

## Mechanism · 改对象与改引用槽位

模型给对象分配 O1、O2 等身份编号。main 的 a、b 和 change 的 p 是三个独立引用槽。`change(a)` 把 a 的引用值复制进 p，main 帧暂停等待。

`p.value = 20` 先解引用 p，再更新对象字段；如果 a 和 b 也指向这个对象，它们会看到同一字段变化。`p = new Box(30)` 分配另一个对象，只替换 p 这个槽中的引用。返回时 p 随栈帧消失，a、b 的绑定保持原样。

Heap 与 Stack 是运行时区域。Method Area 是 JVM 规范中共享的逻辑区域，保存类结构、方法信息和运行时常量池等；不能把它直接等同于每个版本 HotSpot 的某一块物理内存。现代 HotSpot 的类元数据通常在本地 Metaspace，java.lang.Class 对象及关联静态状态涉及 Java 堆，下一层 JVM 课继续展开。

## Experiment · 用编号检验解释

1. 默认值 10，执行 `a = new Box(value)`，再执行 `b = a`。两个变量都指向 O1，堆只有一个对象。
2. 调用 change(a)，新帧 p 也指向 O1。
3. 把值改为 20，通过 p 修改字段。main 的 a、b 解引用都显示 20。
4. 把值改为 30，在 change 中重绑 p。p 指向 O2，a、b 仍是 O1。
5. 返回 main，观察栈只剩一帧；O2 仍在堆表中，但已不从栈可达，完成目标。
6. 把 a 置 null，O1 仍被 b 保持可达；再清空 b。尝试解引用 null 会失败，不能悄悄修改任意对象。

## Conclusion · 返回不等于立即释放对象

模型只包含 Box 的一个整数实例字段，没有继承、对象间引用、JIT 优化或 GC。对象编号不是地址；“在堆中”是这里的抽象，优化器可能把不逃逸对象标量替换，不能从源码 new 机械推断每次物理分配。

方法帧结束移除局部引用，垃圾回收再根据可达性判断对象。把变量、引用、对象和类元数据分别定位，后续讨论类加载、GC 和并发就有了基础。
