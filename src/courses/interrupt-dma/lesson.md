## Problem · 等待设备时，CPU 是否只能空转

设备每隔几个时隙提供一个字节，CPU 同时还有一段后台计算。最直接的方法是不断询问“数据到了吗”。它能完成传输，但检查设备的时间不能用来执行后台程序。换成中断后，是否又能自动省掉数据复制？

## Why · 通知与搬运解决不同问题

总线或互连传递地址、控制与数据，是有限资源。轮询与中断讨论何时处理设备；PIO 与 DMA 讨论谁执行数据搬运。中断处理程序仍然可以逐字节读取设备寄存器并写内存，收到中断本身并不代表已经完成复制。

## Mechanism · 三条完整路径

| 方式           | CPU 行为                                                     | 搬运者     | 完成方式               |
| -------------- | ------------------------------------------------------------ | ---------- | ---------------------- |
| 忙轮询 + PIO   | 先循环检查设备，传完后执行后台任务                           | CPU        | 观察接收计数           |
| 中断 + PIO     | 无事件时做后台工作，有事件时保存 PC、进入处理程序并排空 FIFO | CPU        | 恢复被中断的 PC        |
| DMA + 完成中断 | 配置描述符，执行后台任务，处理完成中断                       | DMA 控制器 | 最后一个字节后通知 CPU |

每次中断入口与返回各占一个教学时隙。中断处理不会推进后台 PC，返回后继续执行被打断的程序。中断不是必然切换到另一个线程；它首先是控制流进入处理程序，调度是另外的决策。

DMA 需要 CPU 提供源、目的与长度等传输描述。真实系统还要协调地址映射、缓存一致性与设备所有权。把 CPU 从搬运中释放出来，仍不能绕过内存带宽或互连争用。

## Experiment · 保持输入相同再比较

1. 默认 6 字节、每 3 时隙到达一个字节，后台任务 12 条指令。单步观察忙轮询的 PC 为什么不动。
2. 运行到传输与后台任务都完成，再对比三种方式，确认内存内容与总线字节数相同。
3. 切换“中断 + CPU 搬运”，观察保存 PC、搬运和恢复 PC。多字节积累时，处理程序可能在一次中断内排空多个字节。
4. 切换 DMA，观察 CPU 后台计算与 DMA 传输出现在同一个时隙。完成数据传输后还需要完成中断返回。
5. 将间隔改为 1，再比较总时隙与开销。结果取决于工作量、到达节奏与成本假设，不能推广为某种方式永远最快。

## Conclusion · 成本模型不是硬件跑分

字节数为 1–8，到达间隔为 1–8，后台指令数为 1–24；后台只使用寄存器，所以可与 DMA 并行。一个时隙搬运一个逻辑字节，PIO 的读设备与写内存合并计数，不代表实际总线事务只需一次。

没有模拟中断优先级、嵌套、屏蔽、IOMMU、缓存一致性、突发传输或 CPU 内存竞争。比较的目的是分开“通知成本、CPU 搬运成本、总线数据量”，不能把这些教学时隙当作真实设备延迟。
