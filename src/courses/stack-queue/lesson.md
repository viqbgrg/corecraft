## Problem · 同样的数据，出来的顺序不同

依次放入 10、20、30。栈先返回 30，队列先返回 10。差别来自允许的端点操作，而不是“数组”或“链表”这个存储名字。

## Why · 用受限接口表达任务顺序

栈适合嵌套调用、撤销和 DFS，队列适合到达顺序、任务排队和 BFS，双端队列允许两端放入与移除。任何一种都需要说明空、满和操作失败时怎样处理。

| 结构              | 放入 / 移除的位置  | 放入 10、20、30 后依次取出 |
| ----------------- | ------------------ | -------------------------- |
| Stack（栈）       | 同一端入、同一端出 | 30、20、10                 |
| Queue（队列）     | 队尾入、队首出     | 10、20、30                 |
| Deque（双端队列） | 两端都允许         | 由每次选择的端点决定       |

这些是抽象的访问规则。数组或链表都可以用来实现它们，本课统一用环形数组，便于把“逻辑先后”与“物理槽位”分开观察。Deque 的两端操作也不意味着它是“两条独立的队列”。

## Mechanism · 环形数组无需整体搬移

本课用固定容量数组实现。head 指向逻辑第一个元素，size 记录元素个数，下一尾插位置为 `(head+size) mod capacity`。队首移除清空旧槽位，再令 head 前进一格；队尾放入使用空槽，索引绕回时复用数组前部。

当 size=0 或 size=capacity 时，都可能 head=tail。这里通过 size 区分，而不是牺牲一个槽位。满时拒绝放入，空时拒绝移除，不覆盖或伪造数据。栈只操作尾端，队列只尾入首出，双端队列可以首入尾出。

### 环形不是把数组里的数转一圈

容量为 4，装入 10、20、30、40 后，物理槽位依次存着这些值，head = 0，size = 4。移除队首只清空槽位 0，并把 head 改成 1。其他三个值仍在原处，不需要依次搬到前面。

此时下一尾插位置是 `(1 + 3) mod 4 = 0`。放入 50 就复用了槽位 0。物理数组成为 `[50, 20, 30, 40]`，从 head 开始沿索引绕一圈，逻辑顺序却是 `[20, 30, 40, 50]`。

| 操作后     | head | size | tail（下一尾插位置） |
| ---------- | ---- | ---- | -------------------- |
| 初始空队列 | 0    | 0    | 0                    |
| 装入四项   | 0    | 4    | 0                    |
| 移除 10    | 1    | 3    | 0                    |
| 放入 50    | 1    | 4    | 1                    |

满时 tail 所指的槽位仍被占用，必须先检查 size，不能只按公式直接写入。空时 head 也不必归零；只要 size = 0，就没有可读元素。

### 从另一端操作

栈把逻辑尾端作为栈顶，弹出位置为 `(head + size - 1) mod capacity`。双端队列首插时先令 `head = (head - 1 + capacity) mod capacity`，再写入新值。加上 capacity 是为了让绕回后的索引保持非负。

这些端点操作都只修改固定数量的槽位和索引，不会因现有元素变多而搬移整条队列。自动扩容或并发访问需要额外规则，本课先保持容量固定。

## Experiment · 一块空间，多次复用

1. 重置，保留 Queue、容量 4。在“放入的值”中依次填写 10、20、30、40，每次点击“队尾放入”。装满后 head = tail = 0、size = 4，继续放入的按钮禁用。
2. 点击“队首移除”，最近移除值为 10，head 变成 1。把值改为 50 再放入，观察物理槽位 0 被复用，逻辑顺序为 20、30、40、50。装满、移除再补满后，实验目标达成。
3. 连续移除剩余四项，核对返回顺序，最后 size = 0，移除按钮禁用。空与满都不能只由 head 是否等于 tail 判断。
4. 选做：切换 Stack，依次 Push 10、20、30，再 Pop 三次，预期返回 30、20、10。要在此模式完成目标，仍需装满、移除再补满。
5. 切换 Deque，先队尾放入 20，再队首放入 10，逻辑顺序为 10、20。队尾移除返回 20，队首移除返回 10。观察 head 绕回，并核对物理位置与逻辑端点。

切换访问规则或容量都会清空结构和当前完成证据。每次记录 **操作端点、返回值、逻辑顺序、head、size、tail**，不要把物理槽位 0 自动当成队首。

## Conclusion · 规则与实现可以分开

容量限 2–8，值限 -99–99。每次端点操作只读写固定数量的槽位与索引。本实验没有自动扩容、阻塞等待、并发安全或无锁内存序；线程安全队列还需要协调多个执行者，后续并发课程会处理这些问题。

自检：队列装满时，覆盖 head 指向的元素可以算“正常入队”吗？本课的队列要求保留所有尚未出队的数据，所以应拒绝。覆盖最旧记录是另一种有损缓冲语义，需要明确约定，不能悄悄替换本课的规则。
