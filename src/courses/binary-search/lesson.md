## Problem · 找到一个，不等于找到第一个

在 `[1,3,3,3,5,8,13,21]` 中寻找 3，多个位置都相等。如果任务是找第一个匹配位置，遇到相等就返回会得到不稳定的答案。

## Why · 把目标改写成边界

我们寻找第一个 `a[i] ≥ target` 的位置，称为 lower_bound。最终位置的值若等于目标，查找成功；否则目标不存在，该位置也是保持有序的插入点。输入必须非递减，实验会拒绝无序输入。

“非递减”允许相邻元素相等。例如对目标 3，默认数组可以分成 `< 3` 与 `≥ 3` 两段：左段只有 1，右段从第一个 3 开始。二分查找利用这个单向变化，逐次排除不可能包含左边界的区域。

如果数组无序，某次比较就不能证明整段可以排除。算法快的原因是输入提供了有序信息，不是因为只要把范围对半切就一定正确。

## Mechanism · 半开区间的不变量

初始 lo=0、hi=n。始终保持 `[0,lo)` 全部小于目标、`[hi,n)` 全部不小于目标，尚未确定的部分是 `[lo,hi)`。

取 `mid=lo+floor((hi−lo)/2)`。若 a[mid] 小于目标，令 lo=mid+1；否则令 hi=mid。每步都严格缩小区间，lo=hi 时结束。hi 可以等于 n，但算法不会读取 a[n]；完成后检查是否真的匹配也必须考虑这个边界。

### 为什么两边更新不同

如果 `a[mid] < target`，有序性保证 mid 左边也都偏小，mid 本身同样不能作为答案，所以左边界跨过它，变成 mid + 1。

如果 `a[mid] ≥ target`，mid 可能正是第一个满足条件的位置，也可能左边还有更早的答案。因此把 hi 收到 mid，保留这个已知的右边界，继续比较它左侧的元素。**相等时不能立即返回，也不能把 hi 改成 mid - 1。**

半开区间 `[lo, hi)` 表示还有哪些元素需要比较，最终边界也可以落在 hi。lo = hi 时，未知区间为空，而不是“没有答案”；此时两侧不变量一起确定了插入位置。

### 默认输入的四次比较

索引从 0 开始，数组是 `[1, 3, 3, 3, 5, 8, 13, 21]`，目标为 3：

| 比较前区间 | 检查的中点   | 比较后区间 |
| ---------- | ------------ | ---------- |
| [0, 8)     | a[4] = 5 ≥ 3 | [0, 4)     |
| [0, 4)     | a[2] = 3 ≥ 3 | [0, 2)     |
| [0, 2)     | a[1] = 3 ≥ 3 | [0, 1)     |
| [0, 1)     | a[0] = 1 < 3 | [1, 1)     |

最后返回索引 1，而不是第二次比较碰巧遇到的索引 2。这正是“找第一个”和“找任意一个”的差别。

一般实现可以写成下面的步骤；最后的长度检查保护了目标大于所有元素的情况：

```text
lo = 0，hi = n
当 lo < hi 时：
  mid = lo + floor((hi - lo) / 2)
  若 a[mid] < target：lo = mid + 1
  否则：hi = mid
位置 = lo
找到目标 = lo < n 且 a[lo] == target
```

## Experiment · 相等、缺失与两端

1. 重置，保留默认有序数组与目标 3。点击“比较一次并缩小区间”，每次先预测下一对 lo、hi，再对照上表。四次比较后得到首个索引 1，基础实验目标达成。
2. 把目标改为 4，重新“查找到结束”。返回“未找到 · 插入点 4”，因为 a[4] = 5 是第一个不小于 4 的值，却不等于 4。
3. 把目标依次改为 -1 和 99，分别得到插入点 0 与 8。8 等于数组长度，表示应追加到末尾，不表示数组中真的存在索引 8 的元素。
4. 输入 `3 3 3`，目标 3，结果仍为索引 0；再试单元素数组 `3`，分别查找 2、3、4，预期位置为 0、0、1，只有目标 3 真正匹配。
5. 选做：输入 `3 1 2`，确认实验提示有序前提不成立，不能继续搜索。修正为 `1 2 3` 后重新开始，实验不会替你悄悄排序。

每轮记录 **比较前的 lo / hi、mid、a[mid]、排除理由、最终位置与是否匹配**。修改输入或目标会清除旧进度，比较次数只属于当前这次查找。

## Conclusion · 快来自可以排除

支持 1–24 个整数，值与目标范围 -99–99。比较次数是 O(log n)，但这建立在数组可以 O(1) 读取中点之上；在单链表中“二分比较”并不自动带来同样的整体复杂度。排序本身的成本也不计入本次查找。

自检：目标不存在时，lower_bound 是否就失败了？它仍正确返回有序插入位置，只是“元素等于目标”这项检查为假。标准 lower_bound 也能处理空数组并返回 0；本实验的输入控件要求至少一个元素，要把接口限制和算法性质分开。
