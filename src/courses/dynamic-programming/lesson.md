## Problem · 一次合理的选择，留下更差的结尾

面额为 1、3、4，目标金额 6。先拿最大的 4，再拿两个 1，需要 3 枚；选择 3+3 只需 2 枚。贪心的第一步看起来最好，却没有得到全局最优。

## Why · 用问题结构证明策略

贪心需要证明某个局部选择可以扩展成最优解，例如通过交换论证。不能因为常见货币体系里“先拿大的”经常有效，就推广到任意面额。

动态规划适用于具有最优子结构和重叠子问题的场景。此处只关心最少枚数，每种面额可无限使用；若最后一枚是 coin，前面必须是金额 x−coin 的最优解，否则整体还可改进。

这里的最优子结构可以直接解释：如果某个凑 6 的最优方案最后用了 3，前面凑 3 的部分却不是最省枚数，就能用更好的凑 3 方案替换它，从而进一步减少总枚数，与“已经最优”矛盾。

不同大金额又会重复依赖相同的小金额。把每个小问题的答案保存下来，就能复用已经比较过的结果，避免反复枚举同一批组合。动态规划的关键是定义状态和依赖，不是仅仅“开一张数组”。

## Mechanism · 状态、初值、转移与回溯

定义 dp[x] 为凑成金额 x 所需的最少枚数。dp[0]=0，其余初始为 ∞。对每个不超过 x 的面额，比较 `dp[x−coin]+1`，取最小值，并记录选中的最后一枚。

金额从小到大求解，正面额确保依赖已经算完。全部候选不可达时保持 ∞。从目标沿“减去最后一枚”回溯，直到金额 0，得到一个真正的方案。平局按较小面额优先，只决定返回哪一个最优方案。

### 从含义写出转移

固定面额集合后，一个状态只需要记录金额 x。对每个 `coin ≤ x`，把“一份凑成 x - coin 的最优方案”再加上一枚 coin：

```text
dp[0] = 0
dp[x] = min(dp[x - coin] + 1)
        对所有 coin ≤ x 的面额取最小值
不可达的前驱不产生可行方案
```

dp[0] = 0 表示不用硬币就能凑成 0，其他状态不能也初始化为 0，否则“还没找到方案”就会被误当成“零枚即可凑成”。∞ 是不可达标记，`∞ + 1` 仍不可达。

### 默认问题的完整状态表

面额为 1、3、4，目标为 6：

| 金额 x | dp[x] | 记录的最后一枚 | 前驱金额 |
| ------ | ----- | -------------- | -------- |
| 0      | 0     | 无             | 无       |
| 1      | 1     | 1              | 0        |
| 2      | 2     | 1              | 1        |
| 3      | 1     | 3              | 0        |
| 4      | 1     | 4              | 0        |
| 5      | 2     | 1              | 4        |
| 6      | 2     | 3              | 3        |

计算 dp[6] 时有三个候选：最后用 1，代价为 dp[5] + 1 = 3；最后用 3，代价为 dp[3] + 1 = 2；最后用 4，代价为 dp[2] + 1 = 3。因此选 3，并不因为它面额最大，而是因为它接上的前驱方案最好。

回溯从 6 开始，取最后一枚 3，剩余 3；再取 dp[3] 记录的 3，剩余 0，得到 3 + 3。记录前驱的好处是可以交付实际方案，而不仅是一句“最少两枚”。金额 5 的平局选择 1 作为最后一枚，是本模型的稳定选择规则，不影响最少枚数。

### 贪心失败有两种情况

面额 `1 3 4` 凑 6，贪心能完成，只是三枚多于最优两枚；面额 `3 4` 凑 6，贪心先取 4，剩余 2，走入死路，但原问题仍有 3 + 3 的解。只有把所有合法最后一枚都纳入转移后，dp[目标] 仍为 ∞，才能在本模型中判定无解。

## Experiment · 最优、次优与无解

1. 重置，保留面额 `1 3 4`、目标 6、Greedy。单步观察剩余金额 6 → 2 → 1 → 0，得到 4 + 1 + 1。点击“对比贪心与动态规划”，看到 DP 用 3 + 3，只需两枚。当前求解结束且完成对照后，实验目标达成。
2. 切换 DP，逐次点击“推进一个选择 / 子问题”，每次求解一个金额。对照上表核对 dp[1] 到 dp[6]，再按“最后一枚”和“前驱金额”手动还原结果。最后重新生成对照，以完成当前模式的目标。
3. 输入面额 `3 4`、目标 6，运行并比较：贪心找不到解，DP 仍得到 3 + 3。指出贪心在哪一次选择后失去了可行的后续路径。
4. 把目标改为 2，保持 DP，运行到结束并重新比较两种策略。dp[1] 与 dp[2] 都是 ∞，这是原问题无解；没有任何允许的正面额能组成 2。
5. 选做：输入 `1 2 5`、目标 10，运行并比较，两者都得到 5 + 5。说明这只能验证当前实例，不能抹去前面的反例。

修改面额、目标或策略会清除旧求解进度。记录 **面额、是否允许重复使用、目标金额、当前 dp 值、选中的前驱、最终方案与枚数**，这样才能检查状态是否足够表达约束。

## Conclusion · 保存状态，也需要控制规模

最多 6 个不同正面额，范围 1–20，目标 1–40。DP 使用 O(金额) 空间、O(金额×面额种数) 候选比较，是依赖金额数值的伪多项式算法，不能只按输入数字的位数说它是多项式。实验不处理有限硬币数量、所有方案枚举、多目标优化或负面额。

“伪多项式”在这里意味着金额从 10 增长到 1000 时，状态数也约增长百倍，虽然输入金额只多了两位十进制数字。面对很大的金额，仍需要评估时间与空间规模。

自检：如果每种硬币只有一枚，还能直接沿用本课状态表吗？不能直接套用，因为 dp[x - coin] 可能已经用过这枚 coin。必须重新表达“还可使用哪些硬币”的约束；更改问题条件后，应重新推导状态与转移。
